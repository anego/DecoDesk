# DecoDesk 要件定義書

## 1. プロジェクト概要

* **アプリ名:** DecoDesk (デコデスク)
* **目的:** 指定ディレクトリ（約40万枚・2.5TB規模を想定）の画像を用いて、高度な合成・加工（ポストカード風、コルクボード風など）を施した壁紙を自動生成し、マルチディスプレイ環境に適用するWindows向けデスクトップ装飾アプリ。
* **ベンチマーク:** John's Background Switcher 同等以上のカスタマイズ性と、巨大なファイルシステム下での圧倒的な描画・検索パフォーマンスの実現。

## 2. 技術スタック

* **開発言語:** C# (.NET 10)
* **UIフレームワーク:** WPF または WinUI (タスクトレイ常駐および設定画面構築用)
* **画像処理ライブラリ:** SkiaSharp (画像合成・エフェクト・描画用)
* **データベース:** SQLite (`Microsoft.Data.Sqlite` 等 / メタデータ管理・高速検索用)
* **OS制御:** `Vanara.PInvoke` 等を利用した `IDesktopWallpaper` (COMインターフェース) の呼び出し

## 3. 機能要件

### 3.1. 基本動作・ライフサイクル

* **タスクトレイ常駐:** システムトレイにアイコンを表示し、右クリックメニューから操作を提供する。
* **実行モード:**
* **インターバル更新モード:** 常駐し、指定した時間間隔で壁紙を自動更新する。更新処理と並行して、バックグラウンドでDBとファイルシステムの同期を維持する。
* **One-shotモード:** PC起動時に1度だけ壁紙を更新し、プロセスを終了する。起動速度を最優先し、DBの同期処理はスキップして既存のインデックスのみを利用する。



### 3.2. 画像データベース管理 (メタデータインデックス)

* **SQLiteによる画像管理:** 対象ディレクトリ内の全画像のパス、解像度、アスペクト比（縦横比）、最終使用日時などのメタデータをDB化する。
* **条件付き高速抽出:** 40万件のレコードから、「直近使用していない」「指定したアスペクト比（例: 横長画像のみ）」といった条件で瞬時にランダム抽出を行う。
* **バックグラウンド同期:** アプリ稼働中、ファイルシステムの変更（追加・削除・リネーム）を検知し、ユーザーの操作をブロックすることなく非同期でDBを最新状態に保つ。

### 3.3. 画像処理・レンダリング (コア機能)

* **ベース機能:** モニター解像度に合わせたアスペクト比の調整（クロップ、余白追加）。
* **複数枚合成:** 複数画像を1つのキャンバスにレイアウト。
* **ポストカード風加工:** 画像に白いフチとドロップシャドウを付与し、任意の角度で傾けて描画。
* **コルクボード風合成:** 背景にコルクボードテクスチャを適用し、画像上部にピンのグラフィックと影を合成して描画。

## 4. 大規模データ対応・非機能要件 (40万枚・2.5TBスケール対応)

* **超高速メタデータ抽出 (フルデコード回避):**
* 初期スキャンや新規ファイル追加時の解像度取得において、画像全体のデコード（メモリ展開）を行わず、バイナリヘッダ（マジックナンバーと先頭数十バイト）のみを解析してアスペクト比を抽出する。


* **メモリ保護を意識したファイル走査:**
* メタデータ収集時は `Directory.GetFiles` によるメモリの大量消費（LOH圧迫）を避け、`Directory.EnumerateFiles` によるストリーム処理を採用する。


* **データベースI/Oの極限最適化:**
* SQLite接続時はWALモード（`PRAGMA journal_mode = WAL;`）を有効化する。
* 大量ファイルのインデックス作成時は、必ずバルクInsert（トランザクション）を使用し、ストレージへの書き込み負荷を最小化する。


* **ファイルシステム監視の堅牢化:**
* `FileSystemWatcher` の内部バッファ最大化、および溢れ（Errorイベント）発生時のフォールバック同期処理を実装する。あるいは、より堅牢な代替手段としてNTFS USNジャーナルの採用を検討する。


* **ゼロ・レイテンシ更新 (Pre-renderingパターン):**
* 壁紙切り替え時のタイムラグをなくすため、次回の壁紙画像（加工済み）はバックグラウンドスレッドで事前生成し、Temp領域に保存しておく。



## 5. 開発・コーディング方針

* **厳格な型付け:** `dynamic` や暗黙的な型変換への依存を避け、堅牢な型定義を行う。
* **早期リターン:** ネストを浅く保ち、ガード節を用いた早期リターンを徹底する。
* **意図を伝えるコメント:** 処理の内容ではなく、なぜその設計・アルゴリズムにしたのかという「理由（Why）」をコメントとして残す。
